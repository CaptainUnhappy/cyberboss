**结论：`-105` 是 4 天前的陈旧故障，当前该端点完全正常。** 唯一的遗留是没人再去验证它。

### 3.2 死锁机制（核心问题）

`scripts/cyberboss-watchdog.ps1`：

- 第 2597 行（`Get-CanaryIdleGateBlockers`）：
  ```powershell
  if ([int]$Snapshot.deferredReplies.pendingCount -ne 0) { $blockers.Add("deferred_replies_pending") }
  ```
- 第 3921 行：只有 `Test-CanaryIdleGate` 通过，才会 `Invoke-CanaryCheck -Reason "routine"`。
- 第 3936 行：否则若 `$freshDurableWork`（= 各队列 pending>0 且均 healthy）为真，则走 `Set-SnapshotCanaryResult -Deferred`。

由于 `deferredReplies.pendingCount=3` **且** 三个队列都 `healthy=true`：

1. `Test-CanaryIdleGate` → 被 `deferred_replies_pending` 阻塞 → 不跑 canary；
2. `freshDurableWork` → 为真 → 记为 "deferred while durable work is actively draining"；
3. canary 永不重跑 → `transport_e2e_unverified` 永存 → `healthy=false` 永存。

**这是一个没有出口的循环。** 看门狗日志每 2 分钟如实重复一次：

```
[2026-09-11 23:31:34] canary verification pending for the configured Azzy target; action=failed; nextDue=2026-09-08T11:47:33.404Z
```

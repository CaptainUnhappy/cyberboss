# Agent Note: 轮次提示词改为「静态说明在前、用户消息与时间在后」

Status: implemented

## Problem

`assembleRuntimeTurnText()`（`src/core/inbound-turn.js`）是入站轮次的文本装配器。它原来的顺序是：

```
1. 用户消息原文                       <- 每轮必然变化
2. 附件/引用边界说明                   <- 静态指令
3. 合并转发隐式任务说明                 <- 静态指令
4. 引用上下文正文                     <- 变量
5. ADHD 输出风格（模板文件）            <- 静态指令
6. 记忆条目                          <- 变量
7. 附件路径 / 视觉描述 / 错误           <- 变量
8. Message time: [时间]               <- 每轮必然变化
```

即**变量打头、静态指令夹在中间**。提示词缓存按**最长公共前缀**命中，任何靠前的变量都会让其后全部失效；把每轮都变的用户消息与时间戳放在最前面，等于主动放弃这一段的可缓存性。

## Decision

`assembleRuntimeTurnText()` 的节顺序改为：

1. **静态指令段**：附件/引用边界说明 → 合并转发的隐式任务说明 → ADHD 输出风格 → 贴纸指引
2. **每轮变量数据**：引用上下文 → 记忆条目 → 附件路径 → 视觉描述 → 附件错误
3. **用户消息原文**（`originalText`）—— 倒数第二节
4. **`Message time: [本地时间]`** —— 永远最后一行

具体约束（现在是事实，改动时须保持）：

- 用户消息**必须是最后一个内容段**，时间戳**必须是最后一行**。
- 静态指令段的**文字与顺序**保持原样，只有位置前移；各段仍按原条件决定是否出现（无附件就不出现边界说明）。
- 边界说明的触发条件保持不变：`图片附件 || 引用上下文 || 存在 origin=quoted 的附件`，且必须有 `originalText`。
- `buildWeFlowInboxTurnText()`（WeFlow 主路径）**不动**：它的 `WeFlow 微信入站（来自大号会话 …）` / `WeFlow 同号人工控制输入（…）` 头是 `isDirectMergedForwardText()` 的解析依据，动它会破坏合并转发识别。该路径的稳定指令来自**静态会话指令**，不在轮次文本里。
- `system-message-dispatcher.js` 的 `buildSystemInboundText()` **本来就正确**（`stableInstructions` → `Trigger:` → `Event time:`），本轮未改，作为对照基准。

## Alternatives considered

- **只把用户消息挪到末尾、静态段留在中间**：改动更小，但静态段仍被变量数据隔开，前缀依然断在第一个变量节上；既然要动就一次排到位。
- **给每段加显式标题（如 `## Current message`）再排序**：可读性更好，但会改变模型看到的措辞，属于与缓存无关的行为变更，收益不明；本轮只动弹词顺序，不改一个字。
- **改 `buildWeFlowInboxTurnText()` 的头部结构**：会破坏 `isDirectMergedForwardText()` 的前缀解析（`[合并转发]` 判定依赖该头），且 WeFlow 路径的轮次文本本来就只有"头 + 正文"，没有静态段可前置。故不动。
- **给 system/人格提示词加时间戳（很多项目的做法）**：那才会真正杀死整段缓存，本项目没有这么做 —— `renderInstructionTemplate()` 只替换 `{{USER_NAME}}` 与代词，人格前缀是静态的，这一点必须保持。

## Consequences

- 收益：同一轮内"静态指令 + 变量数据"的公共前缀不再被首行的用户消息切断；纯文本轮次（无引用/附件/记忆）的提示词退化为"用户消息 + 时间"两段，与改造前相比只是顺序变化，无额外成本。
- 代价：模型看到的**节顺序**变了。语义未改（各段的说明文字一字未动，且边界说明本身就是"本节所指的显式文本"这种与位置无关的表述），但若观察到输出风格漂移，回滚点就是这一处函数。
- 未验证的部分：本项目未接缓存命中率指标，**没有量化前后差异**；本轮只保证"变量在后"这一结构性事实，实际命中率提升取决于运行时（DSH/ACP）如何切分前缀。
- 影响面：仅 `src/core/inbound-turn.js`（`+26/-21`），`npm run check` 通过；`buildWeFlowInboxTurnText` 与 `buildSystemInboundText` 未改。

# Agent Note: 隔离会话内夸克网盘客户端能否完整调用分享链接下载（验证结论）

Status: implemented

## Problem

隔离会话（session 4）已经承担了机器人的收发。同一台机器上另有需求：**让夸克网盘客户端在隔离会话里把一条分享链接完整下载下来**（链接 `https://pan.quark.cn/s/081f01685709#/list/share`），从而不必在用户自己的桌面上弹窗、抢焦点。开工前没有任何事实依据回答三个问题：

1. 客户端会不会接受"带 URL 启动"，还是只能人工粘贴？
2. 分享链接里的内容能不能在会话内完成"保存到网盘 → 下载到本地"这条链？
3. 会话内的**输入注入**（键盘/鼠标）到底能不能用、边界在哪？

这三个问题的答案决定了后续要不要为它写自动化，所以先做一次**只验证、不全量下载**的实测，并把结论固化成可复用的调用契约。

## Findings

**结论：客户端的下载功能可以在隔离会话内被完整"调起"，但这条链在本机账号上被 VIP 权益拦在最后一步——免费档没有本地下载权限。**

| 能力 | 结果 | 证据 |
|---|---|---|
| 带 URL 启动客户端 | **可用** | `Start-Process D:\Tools\QuarkCloudDrive\quark_cloud_drive.exe "https://pan.quark.cn/s/081f01685709"` → 同进程（pid 25692）新开窗口 `hwnd=0xB078C`，标题 `分享链接`，弹出「查看分享链接」对话框 |
| 分享内容解析 | **可用** | 对话框显示分享者 `喜出"外的菠菜`（VIP）、`共 44 个文件 2.5GB 永久有效`、列表 1 项（`许方正味博士性学教室…[MP4]`，43 项，2025/09/20 20:51），默认勾选 1 项 |
| **保存到网盘** | **成功，无需 VIP** | 点击 `保存 (已选1)` 后对话框关闭、视图切到「转存的内容」，第一行即该条目（`今天 15:17`，带「最新」标）；右上空间用量 **2.10/10G → 4.60/10G**（+2.5GB = 分享完整体积） |
| **下载到本地** | **被 VIP 付费墙拦截** | 右键菜单里 `下载` 项存在且可点；点下后弹出 SVIP 购买页（`在线解压免费体验已结束 开通SVIP享 12G 大文件，无限次在线解压`），未见任何下载进度 |
| 下载任务是否被创建 | **没有** | 客户端自身的 `download.db` 只有 schema 与索引（`CREATE TABLE download_task …` / `CREATE INDEX idx_download_order …`），**没有任何任务行**；`C:\Users\cwinprobe\Downloads` 始终只有 `desktop.ini` |
| 客户端在本会话运行 | **正常** | 11 个进程全在 session 4，账号 `cwinprobe`；`user_info` 为加密串（服务端档位/配额读不出来，档位只能从 UI 的付费墙反推） |

隔离会话里的**驱动梯队**（这次逐一实测过，是本次最有复用价值的副产物）：

| 手段 | 会话内可用性 | 说明 |
|---|---|---|
| `PostMessage`（如 `WM_CLOSE`） | **可用且不抢焦点** | 关闭挡住目标的资源管理器窗口，全程不改变前台 |
| `SendInput`（键盘/鼠标） | **可用，但抢焦点** | 实测注入 47 字符返回 `sent=94 err=0`；坐标点击同样生效（一次错位点击把默认勾选切掉了，反证真实生效） |
| `UI Automation` | **对 Chromium 窗口基本不可用** | 夸克主窗口的 UIA 子树只有 2 个元素（`Chrome Legacy Window` + `Intermediate D3D Window`），拿不到按钮；因此只能走"截图定位 + 坐标点击" |
| 屏幕截图 | **可用（有瞬时窗口）** | `CopyFromScreen` 在会话断开的一瞬会报 `句柄无效`，恢复后即成功 |
| 调用客户端私有 SQLite | **只读到 schema** | 会话内无 `sqlite3`；`download.db` 被客户端独占锁定，只能 `Copy-Item` 副本后按字节读字符串 |

## Decision

**本次只固化事实，不为它写自动化**：现有的夸克链路由人工在会话桌面里驱动（需要时用 `cwin-s1-rdp-show` 把客户端挪回屏幕 `(0,0)`），自动化留到"账号具备下载权限"之后再谈。真要写，按上面的梯队组织：`PostMessage` 优先，`SendInput` 兜底，UI Automation 不要指望。

**会话内驱动的既定约束**（踩过并已确认的）：

1. **禁止在会话内跑耗时脚本**。会话内文件队列 `C:\ProgramData\cwin-probe\s4\{in,out,done}` 的 worker 以 `WaitForExit(300000)` 串行执行：本次一个"递归枚举 `HKCU:\SOFTWARE\Classes`"的脚本把 worker 卡满 300 秒，期间保活探针全部无回音（另一篇笔记据此把 `q1..q10` 记成了"另一个 workload 占用"——**那就是本次测试**）。
2. **暂停文件（`rdp-client-hold.txt`）在场时，客户端被最小化不会自愈**。本次 hold 文件存在期间客户端被最小化，会话失去输入桌面（`GetForegroundWindow()=0`、`SendInput` 返回 `sent=0 err=5`），保活只在日志里留 `still unhealthy`；移除 hold 后由 `cwin-s1-rdp-keepalive` 摆正即恢复。做会话内 GUI 自动化前先确认 `s4\keepalive-probe.txt` 是 `setCursorPos=True`，失败就先 `cwin-s1-rdp-show`。
3. **脚本文件里不要写非 ASCII 字面量**。worker 用 `powershell.exe -File` 执行 UTF-8 脚本但按 ANSI 解码，`'夸克'` 之类的匹配会静默失效（按 PID 找窗口、或用已知 `hwnd` 才可靠）。
4. **点击坐标要按比例换算**。截图是缩放预览（1280×800 预览对应 900×620 的对话框实际尺寸，比例 ≈ 1.232），直接拿截图像素点会打偏。
5. **证据落在** `tmp\quark-share-check\`（`q1..q21` 的文本与截图，`tmp/` 已被 gitignore）；会话内原始产物在 `C:\ProgramData\cwin-probe\s4\quark\`。

## Alternatives considered

- **用会话内的 Edge 打开分享页，再点网页上的"下载/保存"**：最强理由是网页版对分享链接支持最完整，也不需要客户端把 URL 当参数；且 session 4 里 `msedge.exe` 与 `msedgewebview2.exe` 本来就在跑。否决原因：默认浏览器是 `MSEdgeHTM` 没错，但网页端要复用客户端登录态才谈得上"拿到文件"，而分享页在网页端同样受同一账号的下载权益约束——它不会绕开付费墙，只会多引入一层 cookie 依赖。
- **用客户端自带的剪贴板下载能力（`preference.json` 里 `clipboardForDownloadEnable: true`）**：最强理由是"复制链接即下载"最贴合 bot 的调用形态（不需要定位窗口、不需要坐标）。否决原因：这个开关的实际语义未知（可能只是"复制文件到剪贴板"或"从剪贴板建任务"），实测窗口里也没找到对应入口，且它触发的仍是同一个被 VIP 拦住的下载动作；要验证它得先有可下载的权限，属于本末倒置。
- **直接调夸克网盘的后端 API（`share` 系列的 token → 文件列表 → 下载直链）**：最强理由是唯一能彻底摆脱 GUI 的路子，且 session 4 内本来就有登录 cookie（`User Data\Default\Network\Cookies`）。否决原因：需要经客户端进程解密 cookie 并复现 `__puus`/签名头，成本与脆弱性都远高于收益；本次只要"能不能用客户端调起下载"，这条留作将来真要脱离客户端时的备选。
- **顺手把会话内队列的超时/隔离问题修掉**（给 worker 加文件锁或给探针单独通道）：最强理由是它确实是可复现的架构缺陷——共享队列让一个重负载脚本就能拖垮保活判定。否决原因：队列的另一端（`scripts/isolated-session/rdp-keepalive.py`）刚由并行会话改过一轮（"探针没回音只跳过、不重连"已入库），此刻再改是同文件竞争；本条只把"队列是串行且超时 300 秒"写成约束。

## Consequences

- **收益**：三个开工前的问题都有了实测答案——URL 启动可用、保存到网盘可用、**下载被账号权益拦住**（这不是代码问题，买会员或换号即可），避免了照着"客户端坏了"的方向白排查；隔离会话里的驱动梯队与五条约束可直接复用。
- **代价**：为了让"保存到网盘"这一步可验证，往该账号的网盘里**真实存入了 2.5GB**（`转存的内容` 第一行，`来自: 分享`），空间用量 2.10/10G → 4.60/10G——这是本次唯一的持久副作用，需要清理就删那一行；VIP 付费墙仍未关闭（弹窗内 `X` 未点中，只影响会话桌面观感）。
- **验证缺口**：付费墙背后"有权限时下载能否真正落盘"**没有被证明**（`download.db` 无任务行只能说明"没创建任务"，不能说明"创建了会成功"）；`download.db` 只读到 schema，没有读出任何单元格内容；`user_info` 加密，账号档位是从 UI 反推的。
- **与既有契约的关系**：本次占用会话内文件队列，曾让 [RDPWrap 隔离会话部署契约](../process/2026-09-18-rdpwrap-isolated-session-deployment.md) 的保活探针超时——那篇的"已知缺口②"与 `## Alternatives considered` 里的"夸克网盘自动化误杀连接"指的就是本次测试；本笔记是它的现象侧记录，部署侧的事实仍以那篇为准。
